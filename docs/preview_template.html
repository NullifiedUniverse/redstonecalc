Put it in your own world A vanilla datapack — no mods. Stand at a corner, run one command, and it places itself over 36 game ticks.

Signal level is height as well as colour. Dust carries a strength from 15 down to 0, losing one per block, so a fading run is a visible ramp and a wavefront is a ridge that travels. Components that switch flash hotter and hold it longer — those are the events; the dust between them is the consequence. At 1× the wait is the real one: a little over two minutes from the lever to the lamps.

01 — What is in there

Every stage is redstone

Nothing is emulated. The pieces are separate modules in the source, each with its own tests, and they compile into one netlist and one placed world:

28 levers on one wall  ──▶ A, B, and the operation
the 8 operation levers ──▶ one-hot latches ──▶ 3-bit opcode
                       ──▶ 10-bit ALU  (8 operations, 4 flags)
                       ──▶ binary to BCD  (combinational double dabble)
                       ──▶ four seven-segment decoders  (leading zeros blanked)
                       ──▶ wiring loom  (32 nets, 128 risers, no crossings)
                       ──▶ four lamp digits + a flag row

One netlist rather than several placed side by side, for a measured reason: the compiler gives each logic stage its own Y plane, and a stage's rail length is set by how many gates sit in that stage. Pipelining the ALU into the converter into the decoders uses disjoint stages and costs no extra rail, while splitting them into separately placed modules would add an inter-module loom for every signal crossing each boundary. The modules are in the source; the silicon is one block.

The keypad cannot burn out

Each key drives a repeater held from the side. Every key also feeds a shared any key is down bus, and each latch's lock is that bus inverted — so all eight go transparent together and the pressed key stores 1 while the rest store 0. One-hot, with no torch in the latch cell to burn.

Leading zeros cost nothing

A digit is shown if it or anything above it is non-zero — one flat OR over every bit from there up. It folds into the decoder's minterms as one more literal, and a term is already an AND, so blanking is free.

The top digit needs no decoder

A 10-bit result cannot exceed 1023, so its thousands digit is 0 or 1 and its upper bits are the constant rail. The decoder folds: impossible values drop out of the sum, and segments lit for every reachable value become constants.

Modules are tested exhaustively wherever the input space allows it, and the whole machine is driven only through the levers a player would touch, with the answer read off the lamps. Nothing reaches inside. What none of that settles

Every figure on this page is measured in a simulator. Two independent engines agree block for block, and each Minecraft rule is written as a minimal circuit you can build and look at — but both were written from the same reading of the same rules, so a shared misreading would produce two engines that agree with each other and disagree with the game, and every test here would still pass. Only running the exported build in a real world settles that.

The engine this page runs on is a third implementation, in JavaScript, and its evidence is thinner still: the whole machine gives 32 correct answers in a real browser. That covers the paths those vectors touch and nothing else. DESIGN §24 says what closing both would take.

03 — Cost

What it costs to keep stable measured

Minecraft kills a redstone torch forced off more than eight times in 60 game ticks, and hazard glitching in a network 36 stages deep does exactly that. Two independent things reduce it, and neither is free.

repeater delayon the earlier buildon this one
2 (4 gt) 2/16, 146 burned 1/16, 140 burned
3 (6 gt) 16/16, 1 burned 5/16, 3 burned
4 (8 gt) 16/16, none burned 16/16, none burned, 2,272 gt

Delay 3 got worse as the machine got smaller, and not for the obvious reason. The torch count did not move — 2,024 either way — and there is more wire, not less: 15,585 repeaters against the old build's 14,464. What fell is how many sit in series. Half the depth, and the answer arrives 292 game ticks sooner, so signals that used to reach a collector several ticks apart now reach it within one. Coincident transitions are what force a torch off repeatedly, so making the machine faster made its hazards tighter.

Delay 4 absorbs it, and that is the row that ships — clean on the harshest input there is, including flipping every lever in the same game tick, which the earlier build's driver had to avoid.

The other lever: how fast the inputs arrive

The harshest input there is: operand pairs chosen to change ten or more levers at once, ten of them, three different seeds, varying how far apart the flips are placed in time. At delay 4 the machine takes all of it:

An earlier version of this table was run at delay 3 and with one seed, and read as a trend in the spacing. It was not: which numbers you type matters more than how fast you type them. At delay 4 neither matters — even changing every input in the same game tick, which aligns every hazard in the machine at one instant and which no player can do anyway. The machine still moves only the levers that differ, two game ticks apart, and so does this page, because it costs nothing and it is what a hand does.

What you are looking at: how the picture is made

One draw call, no second pass, and not one asset. The 249,613 plain structure blocks collapse into stretched runs — 456,558 blocks become 239,571 boxes — so the block grid you can see is drawn by the shader from the world position rather than by geometry: a 418-block slab gets its seams back exactly where its blocks were, for nothing.

Every face is a 16×16 texture at Minecraft's own resolution, sampled nearest so a texel is a texel — and the atlas is drawn into an array at load rather than fetched, which is a page of pixel art in code and about a millisecond. On top of that: a face is shaded by which way it points, the way Minecraft does it; each cell's corners darken twice over where two edges meet, which is what smooth voxel lighting is; each cell's edges catch and lose the key light, which is a chamfer; and a hash of the block's own coordinate varies its shade a little, because a quarter of a million identical stone cubes at one value reads as a bar of paint.

Redstone dust points. A wire is not a blob: a dot powers nothing horizontally, a straight line powers the block behind it, and a cross carries four ways — and which one a cell is decides whether the circuit works. The simulator already computes that mask, because the power rules are evaluated from it, so all sixteen shapes get a tile and the renderer draws the one the simulation is using. Of this machine's 189,125 wires, 118,315 run north–south (the collectors) and 64,464 east–west (the rails), which is the architecture showing through the texture.

Signal level is height as well as colour — a line at 15 stands three times as tall as one at 1, so a wavefront is a ridge that travels. Every lit torch and lamp gets an additive disc, and its colour is splatted into a coarse volume that every surface samples, so a torch does not just look orange, it makes the floor under it orange. The volume is baked in 4 ms and at most once every 90 ms.

Would more kinds of block help? No — three experiments

This machine uses seven kinds of block: 249,613 solid, 189,125 dust, 15,585 repeaters, 2,024 torches, 121 lamps, 62 glass, 28 levers. The torch is the only one that can die, and 1,308 of the 2,024 are inverting taps — at delay 2, 45 of the 56 that burn are taps and the other 11 are all one structure, the display loom's first tower. So the tap is the thing to change.

A comparator in subtract mode with a redstone block on its back inverts too, in the same 2 game ticks, and has no burnout rule at all. Sixty state changes three game ticks apart — seven times what kills a torch — burned out none of them. It should have been the answer. Three measurements say it is not:

side input017131415
comparator output15148210

Its "off" costs a side of exactly 15 — it subtracts a level, not a boolean — and a rail carries as little as 2 at a tap by design. So the tap needs a repeater of its own to restore the rail, and that repeater has to strongly power a block for the dust in the comparator's side cell to read. Strong power reaches adjacent dust at a full 15, so that block drives any rail beside it to 15 with the lever off — which rules out the only cell a repeater reading the rail can reach. Four components have to fit where a torch needs one, in three cells of Z bounded by a rail on one side and a collector on the other. Widening the lattice to make room grows the longest axis by half, and every block of that is more collector, and collector is repeaters, and repeaters are the latency.

The cheap version — a repeater in the stub's cell, costing no space at all because the non-inverting tap already has one there — lost its own A/B: 3% slower at delay 4 for no burnout it did not already have, a wash at delay 3, much worse at delay 2, and it burns five torches out of the Mk II console. Observers have no edge to detect in a machine with no loop in it and cannot hold a level; pistons would make quasi-connectivity load-bearing, which this simulator states plainly that it does not model. Nothing was added.

04 — Use

Made usable, then made honest measured

Correctness says nothing about whether a person can operate the thing. The compiler puts input rails on a four-block Z pitch, so twenty operand bits land spread over eighty blocks, with the keypad on a different level again. Measured in Minecraft's own units — clicks, blocks walked, and how many standing spots a ~4.5 block reach forces, taken from the eyes:

All 28 controls now sit on one wall: fourteen columns two blocks apart, two rows four apart, operation keys first so they fall beside the low-order bits, then bit i with A above B in a single column. The glass walkway in front is not decoration — with your feet level with the bottom row the top row is a 2.6-block reach, which is why the table has no climbing in it.

The last row is the one that matters. Editing a couple of bits is what using a calculator consists of, and that went from 93 blocks of walking to eleven.

Four bugs that all looked like nothing

Every fault in this project had one shape: the build looked healthy, lint passed, and the wrong answer was internally consistent. They are worth more than the successes.

The loom crossed itself

Turn columns were handed out in source order, so a net's final run travelled east past every later column — and where one shared a Z with a taller tower, two segment lines silently merged and the feedback burned 96 torches. Columns now go out in descending feed level, which makes every later tower shorter than the run passing over it.

A cached state that was only mostly right

Relaxing six hundred thousand blocks takes minutes, so the resting state is cached and keyed to a digest of the placed blocks. The first version saved each block's power and lit flag — complete for dust and torches, silently wrong for everything else, because a repeater's output lives in powered and a comparator's in out. Restored worlds looked healthy and computed nonsense.

A run that doubled back over its own lever

The control panel put a lever's dust on its east side and then ran west to the turn column — straight back through the lever, replacing it with plain dust. World.set overwrites without complaint, so the machine went on reporting a lever at a cell that no longer held one. A test now watches every write on the full machine: no two nets may share a cell, and all 28 controls must still be levers.

And one in this page

Reported from a phone: A = 10, B = 72, ADD highlighted, answer 20. Twenty is not a wrong sum — it is 10 << 1, exactly right for SHL. This page holds an operation lever down for 40 game ticks and tracked one pending release, so a second press orphaned the first lever and left it down. Two keys held is not a fault in the keypad: both latch, and the opcode becomes their OR, and SHL|ADD is SHL. The machine was right and the page was lying. It now releases what it holds before pressing, and reads the selected operation back off the one-hot rails rather than remembering which button was clicked — a page that reports the machine cannot disagree with it.

05 — Size

Where the size goes measured

Mk I's lesson was that 85% of the latency was wire. Mk III shows the same problem in a second dimension, and this time the cause is one line in the router. A gate's collector runs along Z from its first tap to an exit, and that exit must sit past the gate's own last tap. The exit becomes a rail for the next stage, whose gates tap it, whose exits must sit past those taps. Over 36 stages the Z coordinate ratchets upward and never comes back down.

The widest stage has 119 gates, which needs 476 blocks of Z. The machine was 1,825 blocks deep. Roughly three quarters of that depth is drift, not logic — and every block of drift lengthens the collectors crossing it, which is where the repeaters go.

06 — Into the game, and what is left

It exports, two vanilla ways

Structure files

A grid of .nbt files a structure block loads, plus a manifest giving each one's offset. Structure blocks stop at 48 blocks a side, so a machine this size arrives as a jigsaw of 373 pieces.

A datapack

/setblock and /fill, batched so a server can run them without stalling, placed relative to wherever you stand. Runs of identical blocks collapse into fills: 456,558 blocks become 71,768 commands.

One convention to get right

Minecraft's repeater facing runs output→input, the opposite of this simulator's; a wall torch's points away from its support. Both are flipped on the way out, and a test asserts each — getting them wrong fails silently.

  1. Alternating collector direction — built. The ratchet above cost three quarters of the depth; reading every other stage's collectors at the far end took the machine from 1,825 blocks deep to 973 and 10% off the answer with it.
  2. The torch-free inverting tap — measured, and it does not fit. A comparator inverts as fast as a torch and cannot burn out, but its "off" needs a side input of exactly 15, and the block that would restore that 15 has nowhere to sit in a tap bounded by a rail on one side and a collector on the other.
  3. A second light bounce. Lights currently wash the surfaces around them out of a coarse volume; what they do not do is bounce off those surfaces onto the next ones. One more splat pass over the lit cells would, at roughly the cost of the first.
  4. Decimal entry. Eight ten-key pads, one per digit position, and BCD-to-binary on the way in — the converter here runs the other way. The control wall would take them unchanged; the logic would not.
  5. A second display beside the controls. The wall fixed entry and did nothing for reading: the digits are 657 blocks away and 192 up.
  6. Multiply and divide, which need sequencing — a clock and a register file — rather than one combinational pass.
Every measured figure comes from the simulator in this repository, on placed blocks. Mk I remains verified: the 4-bit ALU is correct on all 2,048 vectors.
