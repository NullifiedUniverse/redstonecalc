Redstone Calculator Mk II

The first build works and is verified. It was also 88% wire; a transmission-line rewrite took it to 85% and 20% faster. This is the plan for the rest — a decimal machine you can operate, a display that costs almost nothing, and no torches left to burn out.

Everything tagged measured was simulated on placed blocks. Everything tagged projected is an estimate and says so.

The console, running for real

Type a number. Each digit is fed to a redstone BCD→seven-segment decoder, and the seven segment lines it produces drive a display made of redstone lamps. Both modules are simulated block by block, at Minecraft's tick rate — the numerals below are lamps being lit by redstone, not styled HTML.

Why rebuild at all

The Mk I 8-bit ALU settles in 186 game ticks. Its logic is only 14 stages deep, which should cost 28. Walking the placed blocks and attributing every tick on the critical path to a cause explains the gap:

logic 28 gt (15%) rail wire 88 gt (46%) collector wire 74 gt (39%)

85% of the machine's latency is repeaters spent keeping dust alive over distance. Not gates. That single number sets the whole plan, because it collapses three of the goals into one: on this architecture, compact is fast. Every block of wire removed is latency removed, and every block removed is also a block you don't have to look at.

It also means the obvious lever — a cleverer adder — is the wrong one. Carry-lookahead bought 1.7× the logical depth and returned 1.02× on the clock. Acting on the wire instead did work: switching to the wiki's block–repeater–block transmission line, which carries 18 blocks per redstone tick against a bare repeater's 16, took the 8-bit ALU from 234 to 186 game ticks and 5,179 repeaters to 3,996 — with the logic completely untouched, and all 2,048 four-bit vectors still correct. measured

Decision 1 — work in decimal, not binary measured

A binary machine cannot show a decimal answer without a binary→BCD conversion, and double-dabble costs roughly an add-and-compare per bit per digit. Building the datapath in BCD from the start deletes that stage entirely and makes the display a flat 4→7 lookup.

A 3-digit decimal adder including its whole display path is 23% smaller than the binary ALU that still cannot display anything. The catch is depth: 32 stages against 14, because the BCD carry currently ripples from digit to digit and each digit is two chained 4-bit adds.

That fix is now built measured. A digit generates a carry when a+b ≥ 10 and propagates when a+b == 9 — both functions of that digit's own operands, which is exactly what allows lookahead across digits. The correction folds into the same add, since −10 ≡ +6 (mod 16). Result: 963 gates and depth 32 down to 542 and 18 — and no faster on the clock, for the same reason as before. Take it for the gate count, not the speed.

Decision 2 — bit-sliced tiles, not a machine-wide crossbar projected

Mk I routes every stage as a PLA: rails span the whole machine so any gate can tap any signal. That generality is exactly what bought the 45% rail cost. A decimal digit, by contrast, talks almost entirely to itself — only the carry crosses to its neighbour.

So: one tile per digit, cloned along a row, with rails that stop at the tile boundary. A tile is about 30 blocks wide instead of 269, which is the difference between 10 repeaters on a rail and one. Cross-tile wiring shrinks to a single carry line.

Decision 3 — get rid of the torches mechanism measured

With the wire partly fixed, the binding constraint moved. Every large build now burns torches out: Minecraft kills a torch forced off more than eight times in 60 game ticks, and hazard glitching in a deep network does exactly that. The remedy is longer repeater delays, which spread the transitions out — at roughly double the latency.

builddelay 1delay 2
8-bit ALU186 gt, 1 torch burned, 76/648 wrong 360 gt, clean
3-digit BCD, ripple216 gt, 26 burned, wrong 386 gt, clean
3-digit BCD, lookahead208 gt, 37 burned, wrong 400 gt, clean

Comparators have no burnout rule at all, and one inverts: in subtract mode, out = max(rear − side, 0). With a rear constant of 1, any nonzero side gives 0 and a zero side gives 1 — an exact logical inverter, no torch, in the same 2 game ticks a torch takes. Verified in the simulator.

The catch is that its output is only as strong as the rear constant, so a tap built this way needs a repeater to restore it: two redstone ticks against the torch's one. That is the trade, and it is worth taking — because it buys running the whole machine at delay 1.

The copper bulb's rising-edge rule shapes the design: it cannot be driven by a steady level, so latching the answer needs an observer (or a button) to produce the edge — which pairs the two blocks naturally. And the locked-repeater latch has a real protocol requirement found while testing it: the lock must be asserted a tick before the data changes, or the data wins the race and the latch stores the new value instead of holding the old one.

Decision 5 — the display is the memory

A copper bulb holds its own state and is a light source, so the answer register and the screen stop being two different things. Latch the result into the bulbs and the datapath behind them is free to start the next sum immediately, with no separate register bank to build, power, or route.

The seven-segment module already verified here is 168 blocks and settles in 4 game ticks; swapping lamps for waxed bulbs keeps the geometry and adds the memory for free projected. Waxing matters: unwaxed copper oxidises, which changes the light level it emits but not its redstone behaviour.

Decision 6 — player control worth using

0–9 keypad

Stone buttons, one per digit, feeding a shift register. Entry is typing a number, not flipping twelve levers and doing binary in your head.

Lectern as the menu

A comparator reads the open page, so turning to page 2 selects SUB. The menu is a physical book you can label.

Note-block feedback

One pitch on keypress, another when the answer latches. You can operate it without watching the display.

Clear and enter

Two buttons. Clear resets the entry register; enter latches the operand and starts the sum.

The projections rest on the torch-free tap and on the tile change removing most of the remaining rail wire. Those are the two assumptions most likely to be wrong, so they are the two to test first — each measured with the same profiler before anything is cloned.

Build order

Each step is checkable on its own, and each one can fail loudly before the next is worth starting.

  1. Torch-free inverting tap — comparator plus repeater. Removes burnout structurally and lets everything run at delay 1.
  2. One digit tile, bit-sliced. Profile it. If rail wire hasn't collapsed, the plan is wrong and stops here.
  3. Add copper bulbs and observers to the simulator.
  4. Clone the tile three times, wire the carry chain.
  5. Keypad, lectern menu, note blocks.
  6. Join decoder and display in one world — the 21-net corridor: seven feeds per digit, each a two-torch riser to its own transport level, with digits kept in separate tiles so nets never need to cross.
  7. Re-run the whole vector sweep, and the burnout check, on the result.
